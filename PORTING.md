# C / POWER port notes

## Inventory and plan

- MemoryLatency: indexed/direct pointer chasing, page/TLB patterns, MLP,
  array-of-pointers and overlapping store/load forwarding. Common C harness;
  standalone x86/ARM/RISC-V assembler kernels. Fixed 64-byte lines/4K pages.
- MemoryBandwidth: scalar and SIMD streaming reads/writes/copy/add/line flip;
  runtime-generated NOP/branch/call streams. x86 SSE/AVX/AVX512/REP/NT variants;
  ARM/RISC-V assembly. Runtime code is generated by C, not C#.
- CoherencyLatency: pthread CPU-pair ping-pong, CAS and plain load/store modes.
- LoadedMemoryLatency: pointer chasing under throttled streaming read/RMW load;
  standalone assembly workers and pthread harness, missing from root build.
- InstructionRate: architecture-local harnesses and precise assembly sequences:
  integer/FP/vector dependencies, throughput, branches, mixed execution resources,
  loads/stores, crypto. x86 fusion is a separate executable.
- mt_instructionrate: shared pthread harness, textual architecture C includes,
  assembly kernels. Existing POWER file has invalid ELFv1-style descriptors in
  text, incorrect multiply width, wrong FMA branch, uninitialised counters/data.
- CoreClockChecker: AMD MSR/RAPL energy and dependency-chain frequency estimate.
  BoostClockChecker: short dependent-add samples with calibrated reference timer.
- Common/timing is used by mt_instructionrate; other harnesses duplicate wall
  timing. Common/perfmon embeds x86 raw events. Most asm is checked in; normal C
  targets need no generator. GPU OpenCL, C++ variants, Meshsim and C# are excluded.

Plan: shared C build rules/compiler-target detection; memory/coherency kernels;
POWER instruction/MT kernels; explicit unsupported cases; cross-build and tests.
Keep existing x86 assembly and executable names. No C# edits/dependencies.
Inspected the old `power` branch: its pointer preparation targets an older layout
and STLF entries are stubs; used as a reference, not merged wholesale.

## Validation / TODO (updated as work proceeds)

Host is macOS arm64, no native POWER or Linux compiler initially installed.
Hardware timings must be validated on POWER9/10; emulation is correctness only.

## Port status

All seven CPU directories now participate in `make c` (also default `make`).
Compiler-target detection honours CC/TARGET; flags/link libraries live in a
shared include. Per-directory builds and existing Linux executable names remain.
NUMA is opt-in. Cleanup removes named outputs rather than every executable file.

POWER ELFv2 kernels now cover memory latency (including long patterns and STLF),
VSX streaming read/write/copy/add/128-byte line flip, loaded read/RMW with a
relaxed atomic stop flag, instruction dependency/throughput subsets and MT
arithmetic throughput. Generated fetch streams support `instr4` and relative
branches, with `__builtin___clear_cache`. Coherency's no-lock mode now uses
relaxed atomics: still loads/stores, no fences, but no C data race. CAS retains
legacy full-barrier semantics (POWER reservation loop vs x86 locked CMPXCHG).

Clang cross-linked every x86-64 and ppc64le target. ELF headers confirm little
endian, PowerPC64 and ABI flag 2. GCC 14 on emulated POWER9 Linux also built all
POWER targets, plus both NUMA variants. Both compilers' correctness tests pass
under QEMU. Tests explicitly keep assertions enabled (Zig's Clang driver defines
NDEBUG in optimised builds). GCC tests caught a wrong long-pattern return
register; pointer-chase uint32_t return now also obeys ELFv2 zero extension.
Tiny timed samples can hit clock resolution; loop boundary checks are separate.

Correctness fixes encountered: page-pattern element width/partial pages,
missing non-longpattern asm call, MLP bounds/result loop, native page size,
loaded-latency allocation/return/CPU selection bugs, and XCR0-aware AVX512 probing.

## Supported modes and remaining work

- MemoryLatency: C/indexed, direct-pointer asm, longpattern, page-by-page,
  TLB, MLP, AOP; 64/32, 32/16, 64/64 and 128/64-bit store/load pairs. STLF
  sweeps 128 offsets on POWER. MLP exceeding available cache lines reports NaN.
- MemoryBandwidth: scalar C, 128-bit VSX read/write/copy/add/cflip, `instr4`,
  `-branchinterval`. `iterations` counts bytes/array size: RMW uses half as many
  passes; copy reads first half and writes second half. Cflip reverses 16-byte
  chunks within a 128-byte POWER line. Streaming kernels require a 128-byte
  multiple, and a start offset on that boundary; the C harness uses KB/zero.
- LoadedMemoryLatency: read and integer-add RMW load, 128-byte throttle chunks,
  exact byte counts. Reject shared-latency plus add: that corrupts the pointer
  chain. Full large-memory/scaling runs still need hardware testing.
- InstructionRate: 30 named POWER tests covering integer add/mul dependencies,
  XOR/rotate/NOP, taken/not-taken branches, scalar FP64 and vector FP32
  add/mul/FMA, vector INT32 add/mul, reciprocal-sqrt estimate, loads/stores.
  Counts are instructions, not lanes/FLOPs. Throughput uses 8 independent
  destinations and 32-instruction bodies; dependency tests use one chain.
  Mixed execution-resource, renaming/zero-idiom and crypto tests are not yet
  ported. No claimed POWER equivalent for x86 macro-fusion or REP instructions.
- mt_instructionrate: all seven prior POWER arithmetic modes repaired: ELFv2
  entry points, full-word multiply, correct FMA loop, finite FP initialisation,
  exact instruction/element counts and bounded loop remainders. Thread scaling
  and the adaptive wall-time harness still need real-machine validation.
- BoostClockChecker: ordered 64-bit `mftb` around the dependent add chain,
  calibrated against CLOCK_MONOTONIC_RAW. TB ticks are **not** core cycles; reported
  GHz explicitly assumes one cycle per dependent add. Check this on POWER9/10.
- CoreClockChecker's AMD MSR/RAPL test is explicitly unsupported on POWER.
  SSE/AVX/AVX512/NT/REP modes, 2/8-byte NOP streams and x86 call-block generator
  are rejected on POWER. `-pmon` has x86 raw PMU encodings; use external `perf stat`.

No cold-cache latency or prefetch mode existed in these C kernels. Do not add
`dcbf` in streaming loops or treat it as an NT-store replacement; that would
change the measurement. `dcbi` is not an unprivileged generic flush. Generated
code uses the compiler cache-clear facility over the entire modified range.
Ordinary memory tests use CLOCK_MONOTONIC_RAW and compiler memory barriers;
there is no new CPU fence inside their hot loops. Boost uses instruction
synchronisation, not a general memory-store drain. See the assembly comments and
[IBM isync semantics](https://www.ibm.com/docs/ssw_aix_72/com.ibm.aix.alangref/idalangref_isync_ics_instrs.htm).

Native page sizes (including 64K) and POWER9/10 128-byte cache lines are used.
Big-endian POWER and ELFv1 are rejected. Exact physical instruction timings,
unaligned/cross-line forwarding penalties, sustained streaming bandwidth,
SMT/affinity behaviour and boost/frequency estimates require POWER hardware.
QEMU results are only correctness evidence. Legacy non-Linux project files and
ARM/RISC-V paths have not been runtime validated in this pass.

## Commands and validation evidence

Normal builds: see README. Tests: `make -C tests all` to cross-build;
`make check` on the target, or `make -C tests check RUNNER='qemu-ppc64le -L /sysroot'`.
The guard tests cover streaming boundaries/traffic, stop flags, forwarding
alignment, pointer-ring conversion/traversal, partial-page pattern coverage,
small instruction-loop counts and timebase reads. Benchmark outputs are not
performance assertions.

This macOS arm64 run used temporary tools under `/tmp`, never build dependencies:

```sh
# Clang front end via Zig 0.15.2, with Debian GCC runtime archives for linking
ZIG_GLOBAL_CACHE_DIR=/tmp/clambench-zig-cache make -j4 c \
  CC='/tmp/zig-aarch64-macos-0.15.2/zig cc -target powerpc64le-linux-gnu' \
  POWER_CPU=pwr9 \
  LDLIBS='-lm /tmp/clambench-gcc-ppc64el/usr/lib/gcc/powerpc64le-linux-gnu/14/libgcc.a'
# Repeat with -target x86_64-linux-gnu, no POWER_CPU, and amd64 runtime archive.
# Both also built with -Wall -Wextra; legacy unused/sign-compare warnings remain.

# GCC 14 + Debian trixie kernel/initramfs under qemu-system-ppc64:
# -M pseries -cpu power9 -smp 2 -m 1536
make -j2 c CC=powerpc64le-linux-gnu-gcc-14
make -C tests check CC=powerpc64le-linux-gnu-gcc-14
make -C MemoryLatency NUMA=1 CC=powerpc64le-linux-gnu-gcc-14
make -C MemoryBandwidth NUMA=1 CC=powerpc64le-linux-gnu-gcc-14
```

QEMU smoke runs passed: InstructionRate (32,000 instructions), MemoryLatency
C/asm/longpattern/AOP/TLB (128 KB), all six POWER bandwidth modes (2 KB), generated
branches, and coherency CAS/relaxed modes. GCC also executed instruction,
generated-code and coherency smoke tests. x86-64 binaries compile/link; no x86
runtime run here. Full MSR/boost and long MT runs were not executed.

Local logs: `/tmp/clambench-{x86,ppc}-final.log`,
`/tmp/clambench-ppc-vm/{run,gcc-run}.log`; VM setup scripts/initrds are alongside.
`git -c core.whitespace=cr-at-eol diff --check` preserves legacy CRLF files.
Removed the tracked `mt_instructionrate/x86_mt_instructionrate` executable;
C build outputs are ignored. C# sources/tooling were not changed or invoked.


## Raw-clock timing follow-up

All C CPU harnesses (including x86 fusion, ARM/RISC-V instruction variants and
PMU timing) now use `struct timespec` and unsigned 64-bit nanosecond differences.
No gettimeofday/timeval/timezone or microsecond intermediate remains in these
paths. The difference helper handles a borrow across seconds before any float
conversion. Latency, bandwidth, core-energy rate and boost-counter calibration
use the full delta; printed milliseconds are converted only for presentation.
MT worker samples and the 2 s/3 s calibration loop now use nanoseconds, with
zero-sample handling and saturating iteration scaling. Hardware-counter assembly
and its ordering are unchanged. Windows uses QPC, since RAW is Linux-specific.

The old millisecond start/end API remains for GPU/SVM callers outside this pass,
implemented over the new clock; CPU code no longer uses it. C#/GPU/SVM sources
remain untouched.

Validation: all x86-64/POWER targets cross-build with Clang; ARM/RISC-V changed
instruction harnesses compile to objects. GCC 14 POWER builds and both NUMA
variants pass in QEMU. GCC and Clang pass the timing/correctness suites and
POWER smoke tests; a complete single-thread MT suite also passes under GCC.
Timing tests check 1 ns deltas at large epochs, second-boundary borrowing,
zero deltas, raw-clock sampling bounds and calibration thresholds/overflow.
Logs: `/tmp/clambench-{x86,ppc,tests}-raw.log` and
`/tmp/clambench-ppc-vm/{raw-run,gcc-raw-run}.log`.
